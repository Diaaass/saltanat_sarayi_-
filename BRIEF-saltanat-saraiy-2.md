## 1. Технологический подход (повторяем эталон)

### 1.1 Стек
- Чистый **HTML + CSS + ванильный JS**. Без React/Vue.
- Многостраничность на статических `.html`. Общие куски (header/footer/modal/sprite)
  держим как переиспользуемые партиалы (если используется Gulp-пайплайн эталона — через
  include; если нет — выносим в отдельные html-партиалы и собираем).
- **Соглашение об именах классов — BEM**: `block`, `block__element`, `block--modifier`,
  `block__element--modifier`. Утилиты — отдельно (`.container`, `.grid`, `.sr-only`, …).

### 1.2 Fluid-система размеров (ключевая фишка эталона)
Все размеры (отступы, шрифты, ширины, радиусы) задаются НЕ в px, а через множитель,
который привязывает макет к текущей ширине вьюпорта относительно базовой ширины макета:

```css
:root {
  --width-base: 1440;                /* ширина макета на десктопе */
  --width-current: 100vw;
  --width-multiplier: calc(var(--width-current) / var(--width-base));

  --container-width: calc(1240 * var(--width-multiplier));
  --container-padding-x: calc(100 * var(--width-multiplier));
  --header-height: calc(96 * var(--width-multiplier));
}
@media (width <= 768.98px) {
  :root {
    --width-base: 390;               /* мобильный макет Figma = 390px */
    --container-padding-x: calc(20 * var(--width-multiplier));
    --header-height: calc(72 * var(--width-multiplier));
  }
}
```
Пример использования: `font-size: calc(64 * var(--width-multiplier));`,
`padding-block: calc(120 * var(--width-multiplier));`. Значения `N` берём **прямо из Figma в px**.

> Важно: значения `N` снимаются с макета 1:1. Это и даёт пиксель-перфект. На экранах
> шире 1440 контент масштабируется пропорционально (как в эталоне) — это ожидаемо.

### 1.3 Контейнер и сетка
```css
.container { max-width: calc(var(--container-width) + var(--container-padding-x) * 2);
  margin-inline: auto; padding-inline: var(--container-padding-x); }
.grid { --gridColumns:1; display:grid; grid-template-columns:repeat(var(--gridColumns),1fr); gap:.9375rem; }
.grid--2{--gridColumns:2} .grid--3{--gridColumns:3} .grid--4{--gridColumns:4} /* …до 12 */
```

### 1.4 Подключение стилей
- **Critical CSS** (normalize + reset + `:root` токены + базовые `.container/.grid/.sr-only`)
  инлайнится в `<head>` внутри `<style>` — как в эталоне.
- Основной файл `css/main.css` грузится через preload-трюк:
```html
<link rel="preload" as="style" href="css/main.css?v=1.0.0" onload="this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="css/main.css?v=1.0.0"></noscript>
```
- Базовый reset эталона переносим как есть (`box-sizing`, сброс маргинов у `:where(...)`,
  `img,svg,video{display:block;max-width:100%;height:auto}`, `prefers-reduced-motion`, и т.д.).

### 1.5 JS — на data-атрибутах, без фреймворков
Хуки навешиваются через `data-*`, селекторы по классам в JS не хардкодим. По эталону:
- `data-modal-target="modal-feedback"` — открыть модалку; `data-modal-close` — закрыть.
- `data-toggle-target="[data-header]"` + `data-toggle-classname="menu-active"` — бургер-меню.
- `data-page`, `data-header` — корневые маркеры.
- `data-lenis-prevent` — отключить smooth-scroll внутри скроллящихся блоков (меню/модалка).
- **Аккордеоны** площадок — на нативном `<details>/<summary>` ИЛИ на data-хуке
  (`data-accordion`), с `aria-expanded`. Предпочесть нативный `<details>` (доступно, без JS).

**Библиотеки:**
- **Lenis** (smooth scroll) — как в эталоне; нужен в паре с GSAP ScrollTrigger.
- **GSAP + ScrollTrigger** — для свитчера площадок (раздел 10.1): pin + snap + таймлайны.
- **Swiper** — для галереи и, опционально, карточек площадок на мобайле.

Подключать модульно/через CDN с `defer`; на мобайле и при `prefers-reduced-motion` тяжёлый
моушен (pin) не инициализировать (см. 10.1).

### 1.6 SVG-иконки — спрайт
Инлайн-спрайт в начале `<body>` (скрытый `<div hidden>` с `<symbol>`), иконки вставляются
через `<svg><use xlink:href="#icon-name"></use></svg>`. Нужные иконки см. раздел 8.2.

### 1.7 Картинки — `<picture>` с тройным форматом
Каждое растровое изображение — три формата: **avif → webp → png/jpeg** (fallback):
```html
<picture>
  <source srcset="img/hero.avif" type="image/avif">
  <source srcset="img/hero.webp" type="image/webp">
  <img src="img/hero.jpeg" alt="…" loading="lazy" width="…" height="…">
</picture>
```
Hero/первый экран — `loading="eager"` + `fetchpriority="high"`. Остальное — `loading="lazy"`.
Всегда указывать `width`/`height` (против CLS) и осмысленный `alt`.

### 1.8 Шрифты
Подключаем через Google Fonts (preconnect к `fonts.googleapis.com` и `fonts.gstatic.com`):
- **Заголовки:** высококонтрастный сериф. Ближайший аналог с кириллицей — **Playfair Display**
  (вес 400–700). Если в Figma зашит конкретный лицензионный дисплейный шрифт — заменить
  в одном месте (`--font-family-accent`) и положить `.woff2` в `fonts/`.
- **Текст:** гротеск **Manrope** (вес 400–600). Фоллбэк `sans-serif`.

### 1.9 Метаданные / PWA / SEO (как в эталоне)
`<title>`, `<meta description>`, Open Graph, `theme-color`, favicon (`.ico/.svg/.png`),
`apple-touch-icon`, `manifest.json`, `robots.txt`, `lang="ru"`, `<html class="no-js">` +
скрипт снятия `no-js`. Каждой странице — свои title/description/og.

## 3. Глобальные компоненты

### 3.1 Header (`.header`)
- Поверх hero (прозрачный фон на первом экране), при скролле — фиксируется/уплотняется
  (тёмный/кремовый фон — уточнить по поведению; по умолчанию sticky с лёгким фоном).
- **Логотип по центру** (эмблема-вензель + при необходимости вордмарк `SALTANAT SARAIY`).
- Навигация разнесена по бокам от логотипа: слева `О КОМПЛЕКСЕ`, `ПЛОЩАДКИ`; справа
  `ГАЛЕРЕЯ`, `КОНТАКТЫ` (пункты — якоря к секциям).
- Мобайл: логотип + **бургер** (`data-toggle-target="[data-header]"`), меню выезжает оверлеем.
- Пункты меню — гротеск, верхний регистр, межбуквенный интервал.

### 3.2 Footer (`.footer`) — фон `--color-cream`, текст тёмный
- Слева: эмблема + вордмарк `SALTANAT SARAIY`.
- Колонка **НАВИГАЦИЯ**: О комплексе · Площадки · Для каких мероприятий · Галерея · Контакты.
- Колонка **ПЛОЩАДКИ**: Saltanat Saraiy · Terra.ce / Summer Terrace · Aua Shatyr ·
  Night Post Karaoke · Saltanat Saraiy Catering.
- Низ: `©2026 Saltanat Saraiy. Все права защищены.` слева; `Сделано в factum.` справа
  (лого factum — SVG, как `footer-made.svg` в эталоне).

### 3.3 Кнопки (`.btn`)
Две основные формы (обе — «пилюля», скруглённые):
- **Primary (filled):** заливка `--color-espresso`, текст кремовый. Часто со стрелкой `→`.
- **Outline:** прозрачный фон, тонкая рамка `currentColor`, текст по фону секции.
- На бирюзовой/тёмной площадке цвета инвертируются под фон (см. раздел 4 — у каждой
  площадки своя пара кнопок). Иконка-стрелка — из спрайта (`#icon-btn-arrow-right`).
- Состояния: hover (смена фона/инверсия), focus-visible (видимый фокус), `--transition`.

### 3.4 Чипы «подходит для» (`.chip` / `.tags__item`)
Пилюля с тонкой рамкой, гротеск, маленький размер. Цвет рамки/текста = акцент площадки.
Располагаются во flex-wrap. Перед ними — подпись `подходит для` + тонкий разделитель с точкой.

### 3.5 Аккордеон (`.accordion`)
- Нативный `<details><summary>…</summary>…</details>` (доступно, работает без JS).
- В `summary`: заголовок слева + шеврон справа (поворот на 180° при `[open]`).
- Контент: список пунктов с маркером-тире `—`. На десктопе — в 2 колонки, на мобайле — в 1.
- Тонкая линия-разделитель сверху/снизу каждого аккордеона.
- Пример заголовков: `Сервис под ключ`, `Ориентировочная стоимость`, `Зоны террасы`,
  `Коммерческая информация`, `Амплитуда комфорта`, `Залы`.

### 3.6 Фото-карточка площадки (overlay, `.venue__badge`)
Поверх большого фото площадки — небольшая карточка (на светлой площадке белая, на тёмной —
тёмная) с орнаментом сверху/снизу (золото-беж), коротким текстом-описанием и строкой
вместимости (`до 400 гостей` / `до 120 гостей`). На мобайле карточка ложится на низ фото.

### 3.7 Модалка заявки (`.modal` + `#modal-feedback`)
- Кремовая карточка по центру, затемнённый оверлей. Открытие — по `data-modal-target`.
- Заголовок `ОСТАВИТЬ ЗАЯВКУ` (сериф), поля **Имя** и **Номер телефона** (тонкая рамка),
  кнопка **Отправить** (primary, со стрелкой). Закрытие по `data-modal-close`, по клику на
  оверлей и по `Esc`. Блокировка скролла body (`.is-lock`).
- Все CTA-кнопки лендинга (`Забронировать дату`, `Узнать стоимость`, `Оставить заявку`)
  открывают эту модалку.
- Сабмит формы (и в модалке, и в секции «Контакты») при успехе → переход на `thx.html`.
  Бэкенда нет: предусмотреть точку интеграции (атрибут `action`/JS-обработчик) — реальную
  отправку подключим позже. Валидация: имя и телефон обязательны; маска телефона — позже.

### 4.4 Блок «Площадки» — закреплённый скролл-свитчер 5 карточек (`.venues`, `.venue`, `.venue--<id>`)

> **ВАЖНО: это НЕ 5 секций подряд.** Это ОДНА «сцена» с фиксированной раскладкой
> (слева текст, справа фото), через которую скроллом пролистываются 5 площадок с анимацией
> перехода. Полная анимспека и техника (GSAP ScrollTrigger pin + snap + Lenis) — в разделе 10.

**Раскладка сцены (одна на все 5):**
- Слева — текстовая колонка: название-сериф → описание → `подходит для` + чипы → аккордеоны → 2 кнопки.
- Справа — большой медиа-слот с overlay-карточкой (см. 3.6).
- Фон секции — сплошной цвет активной площадки (кроссфейдит при переходе).

**Поведение:**
- Десктоп/планшет: секция **пинится** (sticky к вьюпорту), скролл листает площадки 1→5 со
  **снапом** (фиксация на каждой). После 5-й — открепляется, страница скроллится дальше.
- Контент всех 5 площадок присутствует в DOM (для SEO и доступности) — это «состояния»
  одного свитчера, а не отдельные экраны.
- **Мобайл (≤768.98px) и `prefers-reduced-motion`:** pin/анимацию ОТКЛЮЧАЕМ. Рендерим
  площадки обычным вертикальным стеком — каждая как самостоятельный блок со своим фоном
  (фото+карточка сверху → текст → чипы wrap → кнопки на всю ширину в столбик; подтверждено
  мобильным макетом). Свайп-слайдер (Swiper) — опционально, по согласованию.

## 10. Анимации

### 10.1 Свитчер площадок (раздел 4.4) — СОГЛАСОВАНО, делаем

**Техника:** **GSAP + ScrollTrigger** (pin) в связке с **Lenis** (smooth scroll). Lenis
интегрируется с ScrollTrigger через `lenis.on('scroll', ScrollTrigger.update)` и тикер GSAP.

**Конструкция:**
- Обёртка `.venues` — высота = `(N_состояний) * 100vh` (5 × 100vh = 500vh), внутри —
  «сцена» `.venues__stage` высотой `100vh`, которая **пинится** (`pin: true`) на всё время прокрутки обёртки.
- В сцене: слой фона `.venues__bg` (сплошной цвет), правый медиа-слой `.venues__media`
  (стопка из 5 фото внахлёст), левый текстовый слой `.venues__panel` (контент активной площадки).
- **Снап** между 5 состояниями: `snap: 1 / (5 - 1)` (или `snap: { snapTo: 'labels', duration, ease }`) —
  скролл «листает» и фиксируется на каждой карточке (не плавный безостановочный скраб).

**Хореография одного перехода A → B** (таймлайн на каждый шаг, длительность ≈ 0.6–0.8s, ease `power2.inOut`):
1. **Левый текст (уход):** `x: 0 → -40px`, `opacity: 1 → 0`. Кнопки гаснут с лёгким
   опережением/стаггером (`stagger ~0.04`, уходят чуть раньше текста).
2. **Левый текст (вход, заезжает СЛЕВА):** новый контент стартует `x: -40px, opacity: 0`
   → `x: 0, opacity: 1`. Старт входа с перекрытием (~60% от ухода), чтобы не было «дыры».
   Можно мягкий стаггер по строкам (название → описание → чипы → аккордеоны → кнопки).
3. **Правое фото (кроссфейд с наложением):** новое фото лежит поверх старого; `opacity 0 → 1`
   (+ лёгкий `scale 1.04 → 1` для «оживления»). Старое под ним гаснет/остаётся перекрытым.
   Overlay-карточка вместимости фейдится вместе с фото.
4. **Фон секции (КРОССФЕЙД цвета):** `.venues__bg` плавно перекрашивается в цвет новой
   площадки (бирюза `#1F9FB3` → серый `#F1F1F1` → тёмный `#181818` → беж `#FBF2DE` → крем `#FDFBF2`).
   Реализация: либо tween `backgroundColor`, либо два слоя фона с кроссфейдом `opacity`.
   Вместе с фоном меняется тема контента (цвет текста/кнопок/чипов под фон — см. 4.4 по каждой).
5. «Не тупая смена» = пункты 1–4 оркестрированы в один таймлайн с перекрытиями и easing,
   а не одновременная мгновенная подмена.

**Доступность/устойчивость:**
- Весь контент 5 площадок — в DOM всегда (видимость переключается через анимацию/состояние),
  чтобы быть доступным AT и индексируемым.
- **Мобайл ≤768.98px и `prefers-reduced-motion`:** ScrollTrigger/pin НЕ инициализируем —
  площадки рендерятся обычным стеком (раздел 4.4), без хайджека скролла.
- Инициализацию pin вешать только при наличии GSAP и при ширине > breakpoint; на resize —
  пересоздавать/убивать ScrollTrigger (`ScrollTrigger.matchMedia`).
- Ничего не должно «прыгать» при выключенном JS: дефолтный CSS показывает площадки стеком,
  pin-стили навешиваются только из JS.

### 10.2 Прочие анимации — позже
Остальной моушен (появление секций при скролле, hover-микроинтеракции, hero) куратор
пришлёт отдельно. Разметку делаем «анимация-ready»: обёртки + `data-anim`-хуки, которые не
ломают статичный вид без JS. `prefers-reduced-motion` уважаем везде.
